MOFSynth Fast 3.1.1: Ehull protocol change

Scope
This release derives from mofsynth-fast-3.1-linkerfix-v2-samax.zip. Its linker
normalization, independent complete-set SA/HOMO maxima, and SA-max parent
selection for RMSD/DeltaE are retained. The default Ehull stopping rule changes;
previous production tables, weights, scores and the installed runtime are not
rewritten. A new numerical feature protocol does not establish model validation
with that protocol; no model retraining or calibration is included.

Default stopping rule (all gates must hold simultaneously)
1. Maximum atomic force vector norm <0.01 eV/angstrom.
2. Maximum absolute eigenvalue of the full symmetric Cauchy stress tensor
   <0.05 GPa (0.5 kbar), targeting zero external pressure.
3. Original FrechetCellFilter generalized-force maximum <0.03.
4. Max(E/N)-min(E/N) <=1e-5 eV/atom over the last 5 optimizer updates,
   i.e. 6 successive configurations, using all atoms in the cell.
5. All four gates must pass at 5 consecutive distinct optimizer steps.
   Repeated calls at the same step do not increase the count. A failed gate
   resets the count. The initial configuration alone cannot pass the window.
The optimizer retains Cholesky BFGS and FrechetCellFilter; default inference
remains fp32 with nockpt_merge OFF. These settings were chosen for the local
six-CIF diagnostic campaign, not specified as a combined protocol in the paper.

Limits and failure behavior
Maximum 10000 steps by default; EHULL_MAX_STEPS overrides the step cap.
The existing pipeline --ehull-timeout (default 7200 seconds) remains a process
limit, not a convergence condition. Hitting a cap is a failure, not convergence.
The final structure, per-step convergence.jsonl, opt.log, opt.traj and results.json
are retained when the step cap is reached, but the driver exits nonzero and does
not emit an accepted Ehull JSON or pass the value to model scoring.
Fixed-cell relaxation is not this protocol: --fix-cell is explicitly rejected.
A model must support both forces and stress for this variable-cell route.

Outputs and cache compatibility
results.json records the complete numeric convergence_protocol, protocol_id
mofsynth-ehull-combined-v1, terminal gates, persistence count, final atomic force,
filtered force, principal stress, energy window, step count and termination_reason.
The Ehull result and receipt also record input SHA256 and requested model/solver/
inference settings. The predictor checks these before reusing an Ehull result.
The batch path rejects cached predictions that do not certify the requested
3.1.1 protocol/input/settings. Use fresh work/output directories; old evidence is
not deleted or silently treated as new-protocol output. Existing --from-features
is an explicit no-recomputation path and does not validate/recompute supplied Ehull.

Configuration
Pipeline environment overrides:
  EHULL_ATOM_FMAX=0.01
  EHULL_FMAX=0.03                 (filtered generalized-force limit)
  EHULL_STRESS_MAX_GPA=0.05
  EHULL_ENERGY_WINDOW_STEPS=5
  EHULL_ENERGY_SPAN_PER_ATOM=1e-5
  EHULL_CONSECUTIVE_STEPS=5
  EHULL_MAX_STEPS=10000
All thresholds must be finite and positive; window/persistence must be positive
integers. Overrides are recorded and change the requested protocol signature.
Standalone acceleration/ehull_fast.py has corresponding --atom-fmax, --fmax,
--stress-max-gpa, --energy-window-steps, --energy-span-per-atom,
--consecutive-steps and --max-steps options. Its --scripts argument points to the
existing runtime/qmof-ehull/scripts. Example (existing environment, no install):
  GPU_PYTHON acceleration/ehull_fast.py INPUT.cif --scripts RUNTIME/qmof-ehull/scripts     --device cuda --out-dir NEW_WORK/relaxations --json-out NEW_WORK/ehull.json
Full pipeline example:
  bash predict.sh --prefix RUNTIME --ehull-python GPU_PYTHON --cif INPUT.cif     --label sample --work NEW_WORK --gpu-id 0
--no-fast-ehull / standalone --no-overlap-hull only disable overlapping the hull
load. --ehull-solver orig / standalone --solver orig select the original BFGS
step; all combined convergence gates still apply. --baseline alone selects the
frozen historical pipeline, explicitly outside the default 3.1.1 protocol.

Scientific limits
The earlier local campaign used 6 CIFs x 5 Fast starts, plus a fresh-Hessian
restart and one 0.01 A Gaussian perturbation per endpoint. All 90 stages passed
combined convergence, and all 60 finite endpoint checks passed the preselected
energy/volume criteria. Yet hMOF retained approximately 0.00578 eV/atom spread.
Convergence and stability under a small perturbation therefore do not establish
agreement across raw-start runs, strict local minima or global optimality.
The default production path does not add those diagnostic branches or select the
lowest energy among repeats. Receipt field endpoint_restart_or_perturbation_check
is explicitly 'not executed'. No population-wide accuracy or speed claim follows.

Validation
Run validation/test_ehull_convergence.py with the existing ASE/Numpy environment.
It tests persistence, energy-window excursions, tensor stress, vector force,
step-cap rejection, fixed-cell rejection, cache rejection and serial-hull routing.
The existing linker and RMSD regression tests remain included.
verify.py uses the new convergence receipt and a finite Ehull check rather than
requiring the historical force-only energy constant. This is an installation
smoke check, not a model-performance or global-energy certificate.
